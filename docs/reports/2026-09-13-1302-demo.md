# The demo: every chunk lands as it is encoded, and the fleet's Chrome takes the flag (2026-09-13 13:02)

Page: https://claude.ai/code/artifact/72cf4f61-014a-4794-8329-123e2b2f4f46
Follows: [2026-09-10-0005-gesture-ladder.md](2026-09-10-0005-gesture-ladder.md), which measured the one press per tab; executes [the demo plan](../plans/2026-09-10-demo.md).

## Summary

The demo that sells the concept is built, tested and run by hand, and nothing in it is faked.
A recording page records itself through the extension, every two-second chunk is on the backend before the next one is encoded, a reload of the page rejoins the same recording, a closed tab still lands with every chunk, and the landing page plays the result with a working scrubber and the embed's audio in it.
Two facts the plan left open were settled on the way: Google Chrome 153 honours `--allowlisted-extension-id` for an extension loaded unpacked, so the demo runs in the fleet's own browser with no press of the shortcut, and Playwright's Chromium ignores a policy written to Google Chrome's domain, so a managed Mac that blocks extensions can still run the demo.
The backend was then rewritten in Go as the reference implementation of the upload contract, and the same tests pass against it.
Niels ran the seven beats on real Chrome on 2026-09-13 and reported every one as scripted.

## The flag holds on branded Chrome, unpacked

**Google Chrome 153.0.8010.37 issued a stream id with no shortcut pressed**, measured on 2026-09-10 in the throwaway profile `scripts/demo/chrome.sh` keeps, with `dist/extension` loaded through Developer mode and Load unpacked, and Chrome launched with `--allowlisted-extension-id=oibiheibjolbkmifdocjhkfalginaofm`.
The probe on the landing page answered "Chrome issued a stream id" on a fresh tab.
The spike had proven the flag on Playwright's Chromium only, and the plan's step 0 asked whether the branded build reads it the same way; it does.
Chrome shows a banner, "You are using an unsupported command-line flag", which is what it shows for any switch outside its supported set and says nothing about whether the switch is honoured.
[GRILLING.md, 2a](../GRILLING.md) records the answer.

The fleet's Chrome is not launched with the flag, so the deployment answer is unchanged: one press of Cmd+Shift+Y per tab, unless the client starts Chrome through a launcher that passes the flag.

## What the code met that the plan did not say

**A closing tab ends the captured track before `tabs.onRemoved` fires.**
The plan had the service worker stop the recording on `tabs.onRemoved`; in every measured close the offscreen document had already finished on the track's `ended` event, so the service worker's stop found nothing to stop.
Both paths now end in the same finished record and neither treats the other's win as a failure; the reason on the backend reads `capture-ended` for that reason.

**The macOS CI runner has no ffmpeg.**
The first run of the pull request failed with the backend row reading `failed (ffmpeg: spawn ffmpeg ENOENT)`, so no stop finalized and both tests waited on an event that never came.
The build job now installs ffmpeg with Homebrew, the demo test accepts a finalize that lands before its stop assertion, and the spike test's navigation wait outlasts the recording page's ten second fallback; [run 34523690547](https://github.com/njoubert/nimbus-tab-dvr/actions/runs/34523690547) is green.

**The build deleted the embed placeholder.**
`go:embed` cannot reach outside the module, so `build.sh` copies `dist/demo` into `backend/static`; its `rm -rf` removed the tracked `.gitkeep` before the commit, and a fresh checkout in CI had no file for the pattern to match.
The copy now recreates the directory and touches the placeholder; [run 34570012657](https://github.com/njoubert/nimbus-tab-dvr/actions/runs/34570012657) is green.

**A merge can miss the last push.**
Pull request 5 was merged at the CI fix, before the Chromium launcher commit reached the branch; that commit went in on its own as pull request 6.

## A managed Mac that blocks extensions still runs the demo

**Every Google Chrome channel and copy on a Mac reads the policies its MDM writes for `com.google.Chrome`**, so a second Chrome does not escape a block on extensions.
`scripts/demo/chrome.sh --chromium` launches Playwright's Chromium, a Chrome for Testing build, with `--load-extension` and the flag, and needs no Load unpacked.
Measured on 2026-09-10: with a marker policy, `HomepageLocation`, written to `com.google.Chrome` on the development Mac, a headed Chrome for Testing showed nothing on `chrome://policy`; the marker was removed afterwards.
The positive control, the same marker written to Chrome for Testing's own domain, was not run, so the claim rests on that negative and on macOS keying policy by bundle identifier.

## The backend is Go, as the reference implementation

[Pull request 8](https://github.com/njoubert/nimbus-tab-dvr/pull/8) replaced `scripts/demo/serve.mjs` with a standard-library-only module at `backend/`, the same routes and JSON, `http.ServeFile` for ranges, ffmpeg for the remux, and the demo pages embedded so `dist/backend/nimbus-demo-backend` runs the whole demo as one file.
By hand it answered chunk, stop, list, a 206 range response, the CORS preflight and delete as the Node server did, with a 6.347 s remux of a spike recording; all five tests pass against it.
The decision and its costs are in that pull request's body.
