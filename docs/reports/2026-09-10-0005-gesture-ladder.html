Gesture ladder: a real keystroke is the invocation, and the grant survives a reload

With Accessibility granted to iTerm2, the spike test's gesture ladder ran with the allowlist flag off, and the second rung worked. One Cmd+Shift+Y sent as a real macOS keystroke through System Events invoked the extension on the tab, and after it three start and stop cycles, a page reload, a killed offscreen document and an audio capture all ran with no further gesture. The probe after the reloaded page stopped its recording was granted without another keystroke, so a grant earned by invocation survives a same-origin reload.

This is the deployment path: the fleet's Chrome is not launched with the flag, so a recording needs one invocation per tab, and that invocation is now shown to be one keystroke or click that the rest of the tab's life inherits.

What it decides

  • One invocation per tab is a keystroke or a click, once. The application can tell the user exactly that on its landing page.
  • The grant outlives a reload. The documentation says a same-origin navigation keeps it and is silent on reload; this run says reload keeps it too.
  • The test covers both paths: ./build.sh test with the flag, which CI runs headless, and NIMBUS_ALLOWLIST=0 ./build.sh test for the keystroke on a Mac whose terminal has Accessibility.

Verified and unverified

Verified by running: everything above, on Playwright's Chromium 153.0.8010.12, headed, by Niels in iTerm2 on 2026-09-10.

Not measured: the toolbar click; the same on Google Chrome 150, which cannot load the extension unpacked; whether a grant survives a cross-origin navigation, which the documentation says it does not.
